# مصفوفة قبول K2 والمضيف — غير منفذة

هذه حالات مستقبلية للمراجعة، لا تمثل اختبارات ناجحة أو فشلًا حاليًا. تُنفذ بعد اعتماد العقود وبناء الحدود الفعلية؛ يجب إظهار نتائج قابلة للتكرار، وتحديد الاختبارات التي تحتاج مضيفًا أو متصفحًا حقيقيًا بدل الاكتفاء بمزود مزيف.

| الحالة | الإعداد والفعل | النتيجة المطلوبة |
|---|---|---|
| مستخدمان | مالك A يحاول الوصول لسجل B | رفض موحد دون محتوى أو كشف وجود غير لازم |
| وكيل بلا منحة | وكيل A يقرأ أو ينشئ في مساحة A بلا منحة | رفض ولا أثر |
| منحة قراءة | A يمنح وكيله قراءة سجل محدد | قراءة السجل فقط، ورفض إنشاء أو قراءة سجل آخر |
| منحة إنشاء | إنشاء في مساحة مصرحة ثم في مساحة أخرى | نجاح المصرح ورفض الآخر دون خلط ملكية |
| مساحة مشتركة | منح وكيلين صلاحيات مختلفة | كل وكيل يحصل فقط على عملياته ونطاقه |
| تزوير حقول | واجهة تعرض `ownerId`/`agentId`/`approved` تخص آخر | تجاهلها كدليل ورفض الانتحال؛ اختبار على مضيف فعلي |
| منح ذاتي | وكيل يطلب أن يمنح نفسه وصولًا | رفض ولا تُنشأ منحة |
| إلغاء منحة | طلب بعد التزام الإلغاء | رفض بعد إعادة التشغيل أيضًا، دون وعد بسحب بيانات مكشوفة سابقًا |
| سباق الإلغاء | باريرات تحكم بترتيب إلغاء المنحة والأثر | الإلغاء أولًا يمنع الأثر؛ الأثر المكتمل أولًا يُسجل بصدق |
| انتهاء منحة | مضيف موثوق يتجاوز وقت الانتهاء | رفض عند الأثر، مع اختبار فشل الساعة وفق السياسة المحددة |
| موافقة | رفض/انتهاء/تغيير حمولة/إعادة استخدام | لا أثر، ولا قبول بموافقة تخص طلبًا آخر |
| تكرار الطلب | نفس مفتاح idempotency ونفس/حمولة مختلفة | نتيجة واحدة حيث توجد ذرّية، وتعارض للحمولة المختلفة |
| نتيجة مجهولة | تعطل بعد إرسال أثر لا يمكن التحقق منه | `unknown` دون إعادة عمياء |
| تدقيق | نجاح ورفض وفشل سجل | لا تسريب نص أو مفاتيح، والتصرف يتبع سياسة الفشل المحددة |
| المنحة والموافقة | منحة موجودة مع غياب الموافقة التي تشترطها السياسة، ثم موافقة موجودة دون منحة لازمة | كلا الطلبين يُرفض؛ `approveCreate` لا يُتجاوز |
| عملية دون شرط موافقة | قراءة أو عملية v2 مستقبلية لا تشترط السياسة لها موافقة، مع منحة سارية وبقية الشروط | تمضي العملية المصرح بها دون اشتراط موافقة غير منصوص عليها؛ إنشاء v1 يحتفظ بشرط `approveCreate` |
| ربط محول v1 | طلبان متزامنان لهويتين ونطاقين عبر المحول إن اعتُمد | لا يتشارك السياق أو الموافقة، والتحقق لكل أثر؛ إن تعذر الإثبات لا يُستخدم المحول |
| سجل قبل الأثر | إخفاق حجز سجل تدقيق دائم قبل عملية حساسة | رفض دون أي كتابة أو أثر خارجي |
| سجل بعد الأثر | تحقق الأثر ثم فشل أو غموض تسجيل النتيجة | `unknown`/تعافٍ، دون إعادة تلقائية أو ادعاء أن الأثر لم يقع |
| استعادة منحة ملغاة | استعادة معروفة لنسخة سبقت إلغاء منحة | منحة النسخة غير فعالة، ولا تُعاد إلا بمنحة جديدة صريحة بعد مصادقة |
| rollback خفي | إرجاع أو نسخ ملف خارج مسار المضيف | لا يُعلن اكتشافه دون مرجع مستقل؛ يمنع الوصول أو يُسجل القيد بوابة مفتوحة |
| ساعة راجعة | تراجع الساعة أو غياب وقت موثوق بعد إعادة تشغيل | رفض/تأجيل منح وموافقات محددة بوقت، بلا إطالة صامتة |
| تحقق الوقت بعد إعادة التشغيل | إعادة تشغيل/استعادة دون دليل مستقل، ثم تقديم دليل غير موثوق أو معاد تشغيله | تبقى الحالة `unverified` وتُرفض أو تؤجل العمليات الزمنية؛ لا يُعتبر ثبات ساعة القاعدة دليلًا |
| بصمة وتدوير | نص قصير، تغيير مفتاح HMAC، انتهاء مدة الاحتفاظ أو فقد المفتاح | لا SHA غير مملحة للحمولة الحساسة؛ حالة غامضة تُراجع ولا تعاد تلقائيًا |
| فصل التكرار والحمولة | نفس المفتاح مع حمولة مماثلة ثم مختلفة | إعادة الحالة المصرح بها دون أثر جديد، ثم رفض التعارض |
| تدوير متزامن | عاملان يستخدمان إصداري HMAC مختلفين لمفتاح عميل واحد | حجز واحد أو رفض آمن؛ لا إنشاء طلبين بسبب اختلاف إصدار الهضم |
| مرجع freshness غائب | تشغيل K2 أو فقد الشاهد أو غموض التزامه | لا تفعيل لصلاحيات K2 المحفوظة ولا fallback إلى v1؛ لا ادعاء بكشف rollback |
| قيم SQLite إلزامية | إدخال `NULL` إلى `operation` أو `state` أو `scope_kind` | رفض بقيود `NOT NULL` بالإضافة إلى `CHECK` على اتصال فعلي |
| مسار التفاف | استدعاء واجهة قديمة أو مخزن مباشر من العميل | المضيف لا يعرضه ولا يتحول إليه بعد رفض v2 |
| ترحيل | مصدر v1 متسق مع WAL، تعارض أو فساد أو توقف | الأصل والنسخة قابلان للاستعادة، دون تفعيل هدف جزئي |
| قيود SQLite مركبة | وكيل أو سجل من مالك/مساحة أخرى، أو نطاق سجل مع `record_id` فارغ | ترفض المعاملة حتى عبر اتصال جديد، مع تفعيل وفحص المفاتيح الخارجية فعليًا |
| ترتيب التدقيق والزمن | `occurredAt` مع ثقة غير مؤكدة وتسلسل جلسة؛ إعادة تشغيل أو استعادة | يبقى الوقت `unverified`، التسلسل ضمن الجلسة فقط، ولا يُدّعى ترتيب عالمي أو كشف rollback |
| توافق v1 | بناء الحزمة القديمة واختبارها وفحص صيغة v1 | بقاء السلوك والنسخة القديمة دون تغيير صامت |
| عزل النقل | جلسة مزورة، CSRF، Host/Origin غير معتمد | رفض على مضيف حقيقي، لا على mock وحده |

## خط الأساس الحالي

على `3442b34`، في بيئة العمل بتاريخ 2026-11-07 باستخدام Node `v22.22.3` وnpm `10.9.8`: `npm ci --ignore-scripts --no-audit --no-fund`، و`npm run typecheck`، و`npm run build`، و`npm test` نجحت محليًا؛ 25 اختبارًا قائمًا نجحت. `node:sqlite` أصدر تحذيرًا بأنه تجريبي. هذا دليل محلي على اختبارات النموذج الحالي، **وليس** اختبارًا لحالات K2 أعلاه ولا نتيجة GitHub CI ولا اختبار تكامل Lovable. لا يوجد Lint مهيأ للحزمة في خط الأساس.
