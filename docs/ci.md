# فحوص CI لنموذج النواة

يختبر سير GitHub Actions في `.github/workflows/ci.yml` حزمة `packages/kernel` الموجودة فقط، عند الدفع وطلبات الدمج إلى `main` أو التشغيل اليدوي. يستخدم Node 22 بدل Node 20 لأن المحول يستخدم `node:sqlite` ويدعم Node 22.13 فأحدث. ثُبّتت إجراءات GitHub بمعرّفات commit، وتُمنح العملية صلاحية قراءة المحتوى فقط، دون أسرار أو نشر أو إنشاء إصدار. يُحفظ كاش تنزيلات npm اعتمادًا على ملف القفل، وليس `node_modules`.

## الفحوص

من `packages/kernel` وباستخدام Node 22.13 أو أحدث:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run lint
npm run typecheck
npm test
npm audit --audit-level=high
```

يشغّل `npm test` البناء قبل اختبارات Node، ولهذا لا تتكرر خطوة بناء منفصلة في CI. يستخدم فحص Lint قواعد Biome الموصى بها؛ فحص تنسيق شامل أو formatter مستقل غير مُفعّل بعد. `npm audit` يستعلم سجل npm ويفشل عند ثغرة مصنفة عالية أو حرجة، أو تعذر إجراء الفحص؛ قد ينجح مع ظهور تحذيرات متوسطة أو أقل، لذا يجب مراجعة تقريره ولا يعني النجاح عدم وجود ثغرات. تعتمد النتائج على بيانات السجل المتاحة وقت التشغيل. لا يشمل الفحص مراجعة أمنية شاملة أو تدقيق تراخيص التبعيات.

## الحدود

- لا توجد حاليًا حزمة Python أو واجهة Lovable أو تطبيق Edge في المستودع؛ لا تنفذ هذه العملية اختبارات تلك المكونات ولا تدعي توافقها. عند وصول مصدرها تُفحص سكريبتاته وتُضاف وظائف مناسبة على حدة.
- لا يتضمن سير العمل نشرًا أو رفع artifacts أو تفعيل خدمات مدفوعة. لا يضمن حساب GitHub حدودًا مجانية أو وقت تشغيل دائمًا؛ تُراجع سياسات الحساب وحصصه إذا تغيرت.
- فشل الفحوص يضع حالة فشل على التشغيل، لكنه لا يمنع الدمج وحده: جعل الفحص مطلوبًا يتطلب إعداد حماية فرع أو ruleset لدى مسؤول المستودع. لا يغير هذا التحديث إعدادات حماية `main` ولا يدمج طلبًا.
- نجاح CI لا يثبت أمان K2 أو عزل الهوية أو حماية rollback أو تشفير البيانات. تبقى هذه قدرات غير منفذة ومعايير قبول مستقلة. نتيجة GitHub الفعلية لا تُعرف حتى يعمل السير على الخادم؛ الفحوص المحلية ليست CI.
