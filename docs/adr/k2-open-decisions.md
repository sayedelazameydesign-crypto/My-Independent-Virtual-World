# سجل قرارات K2 المفتوحة

**الحالة العامة: مقترحات للمراجعة، لم يُعتمد أو يُنفذ مصدر وقت أو مرجع rollback أو مخزن مفاتيح.** تبقى سياسة الرفض الافتراضي، ولا تصبح K2 آمنة أو جاهزة بمجرد اختيار اسم تقنية. تُراجع أدلة الاختبارات على بيئة التشغيل الحقيقية قبل تغيير الحالة. لا يفترض هذا السجل خدمة مدفوعة أو عتادًا خاصًا.

## ADR-01 — إثبات الوقت المستقل

- **القرار المؤقت:** يبدأ المضيف بعد التشغيل/الاستعادة بحالة `unverified`؛ لا تُنفذ الموافقات والمنح ذات الانتهاء حتى يُقبل دليل وقت موثوق. لا يُعد وقت النظام أو سجل داخل قاعدة قابلة للاستعادة دليلًا. الساعة الرتيبة تقيس مدة الجلسة فقط ولا تثبت UTC بعد إعادة التشغيل.
- **البدائل قيد التقييم:** مصدر محلي موثوق منفصل له خصائص يمكن إثباتها، أو مصدر خارجي اختياري مصادق عليه ومصرح به، أو البقاء في حالة رفض دون مصدر. لا نفترض توفر أي بديل؛ إدخال وقت يدوي ليس إثباتًا تلقائيًا.
- **معيار قبول المصدر:** إثبات الأصالة والحداثة ومقاومة إعادة التشغيل ومرجع ثقة مستقل، وحد أقصى للخطأ وعمر الدليل والانحراف، والتعامل مع الفقد وإعادة التشغيل والاستعادة. هذه الأرقام وآلية التحقق لم تُحسم. المصدر أو مفتاحه إذا أمكن إرجاعه مع قاعدة البيانات لا يثبت الاستقلال.
- **الأدلة المطلوبة:** اختبارات على مصدر حقيقي للانقطاع، والدليل المعاد أو القديم، والتلاعب والتراجع وإعادة التشغيل واستعادة نسخة؛ يجب أن يفشل مغلقًا. mock وحده لا يثبت ثقة الزمن.

## ADR-02 — حماية rollback الخفي

- **القرار المؤقت:** في الاستعادة المعروفة تُحجر المنح والجلسات والموافقات وتُراجع قبل أي منح جديدة. لا تستطيع قاعدة قابلة للاستعادة إثبات أنها لم تُنسخ أو تُرجع خارج المضيف.
- **البدائل قيد التقييم:** مرجع مستقل يحفظ إصدارًا/حالة freshness موثقة خارج نطاق رجوع البيانات، محليًا إن ثبتت خصائصه أو عبر شاهد خارجي اختياري مصرح به. لا مفاضلة نهائية أو عتاد مضمون. ملف أو سجل في النسخة نفسها ليس مرجعًا مستقلًا.
- **قيد التشغيل المقترح:** اختير الرفض الافتراضي لتفعيل صلاحيات K2 المبنية على حالة محفوظة عند غياب دليل freshness مقبول، بلا fallback تلقائي إلى v1؛ التفاصيل في [مراجعة DDL](../k2-ddl-v2-review.md). يلزم تحقق عند بدء المضيف وبعد الاستعادة وقبل السماح بالعمليات المحمية، وبروتوكول متزامن للمنح والإلغاء وتحديث المرجع. عند فشل التحديث أو تعارض الحالة أو غموض الالتزام يفشل مغلقًا وتُراجع الحالة؛ المعاملة المحلية وحدها لا تضمن ذرية الشاهد الخارجي.
- **الأدلة المطلوبة:** اختبارات نسخة قديمة بعد إلغاء، واستنساخ خفي، وتحديثات متزامنة وتعطل بين قاعدة البيانات والمرجع، وفقد المرجع أو استعادته. إن تعذر التحقق فعليًا تبقى البوابة مفتوحة ولا يُدّعى اكتشاف rollback خفي.

## ADR-03 — إدارة مفتاح HMAC للتكرار

- **القرار المؤقت:** فصل `idempotencyKeyDigest` لتحديد المفتاح عن `requestFingerprint` للتحقق من الحمولة، مع تقييم `HMAC-SHA-256` وتمثيل حتمي وإصدارات وعلامات نطاق مستقلة كما في [مراجعة DDL](../k2-ddl-v2-review.md)؛ لا تخزين SHA-256 غير مملح لمحتوى حساس قصير، ولا اعتبار HMAC بديلًا للمصادقة أو الموافقة.
- **البدائل قيد التقييم:** مخزن أسرار محلي مناسب مستقل عن قاعدة البيانات والنسخ العادية، أو آلية موثوقة أخرى بعد مراجعة خصائصها. لا يُفترض وجود مخزن مفاتيح حاليًا ولا يرسل المفتاح للواجهة. مخزن في الملف نفسه أو النسخة نفسها لا يحقق الفصل المطلوب.
- **قبل الاعتماد:** تحديد معرّف إصدار المفتاح، والتوليد والصلاحيات، والاحتفاظ بفترة طلبات حية محددة، والتدوير دون كسر التحقق، والتخلص الآمن بحدود البيئة، وفقد المفتاح واستعادة البيانات. عند تعذر مقارنة طلب حي بسبب فقد المفتاح تُراجع الحالة `unknown` ولا يُعاد الأثر تلقائيًا. بعد انتهاء مدة الاحتفاظ لا يُضمن منع التكرار إلى الأبد؛ لا إعادة آلية لأثر قديم دون تسوية. المدد وآلية التمثيل ومكان التخزين لم تُحسم.
- **الأدلة المطلوبة:** اختبار عزل المفتاح، وسرية الحمولة القصيرة، ونفس المفتاح/حمولة مختلفة، وتدوير مع طلبات حية، وفقد أو استعادة المفتاح والتعطل. نتائج المحاكاة لا تثبت أمان مخزن الأسرار الفعلي.

## دليل حالة السجل الزمني المقترح

يفصل التدقيق بين `occurredAt` الذي يبلغ به المضيف وبين `timeTrustState` (`unverified`/`verified`)، و`bootSessionId` و`sequence`، و`trustedProofRef` اختياري عند وجود دليل مقبول. يُنشأ معرف تشغيل جديد لكل عملية تشغيل، ويُحفظ ترتيب تسلسلي لكل جلسة؛ لا يدعي هذا ترتيبًا عالميًا بين الجلسات أو مقاومة حذف/إرجاع السجل. الدليل المرجعي لا يعني ثقة تلقائية أو وجود مصدر وقت جاهز، ويجب ألا يتضمن محتوى حساسًا.
