# خطة ترحيل v1 إلى ذاكرة مقيّدة — مقترح

**لا تنفيذ أو ترحيل بيانات في هذا التغيير.** تتطلب كل خطوة لاحقة اختبارًا وموافقة المستخدم، خصوصًا التعامل مع البيانات الحساسة أو استبدال أي ملف. المصدر والنسخة الحالية غير مشفرين؛ لا يوصفان بأنهما آمنان لمجرد إنشاء مخطط جديد.

## خط الأساس والتوافق

- SQLite الحالية `notes(id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL)` و`user_version=1`؛ لا مالك أو مساحة أو منح. واجهة `SqliteNoteStore` تبقى كما هي، ولا تُغير القاعدة الحالية تلقائيًا.
- النسخة الحالية `mivw.notes` v1 JSON plaintext بحد 10,000 سجل و50 MiB، والاستعادة الحالية إلى مخزن فارغ. تبقى الصيغة ومعناها وسلوكها دون تغيير. صيغة مستقبلية محكومة بالملكية أو مشفرة تتطلب معرفًا وإصدارًا مختلفين، ولا يُدّعى دعم البيانات الأكبر قبل إثباته.
- لا يتاح للمضيف الآمن الوصول عبر واجهة v1 الخام دون حوكمة؛ بقاء v1 للتوافق لا يعني استخدامه كمسار تجاوز بعد رفض طلب v2.

## تصميم بيانات مبدئي — ليس DDL منفذًا

في مخزن جديد منفصل تُبحث جداول للمستخدمين الموثقين، الوكلاء، المساحات، السجلات، المنح، وربط معرفات المصدر بمعرفات الهدف؛ سجلات الطلبات/الموافقات منفصلة وفق عقد المضيف. يلزم تعريف قيود فريدة ومفاتيح خارجية تمنع ربط مالك أو مساحة أو وكيل تابع لمالك آخر، وفهارس للاستعلام حسب المالك والمساحة والمنحة. تُحدد سياسات الحذف والتعارض وانتهاء المنح ومعاملات الإلغاء قبل اعتماد المخطط. لا يُفترض أن هذه الجداول أو المصادقة موجودة.

## مسار ترحيل مقترح

1. **تحديد المصدر والمالك:** يختار المستخدم الموثق قاعدة قديمة أو ملف JSON، ويؤكد المالك ومساحة وجهة جديدة. لا تنسب البيانات لأوّل مستخدم أو وكيل تلقائيًا؛ لا تُنشأ منح للوكلاء تلقائيًا.
2. **نسخة أصلية قابلة للاستعادة:** بوسيلة تحقق لقطة SQLite متسقة تشمل معاملات WAL أو بإيقاف الكتابة بطريقة موثوقة؛ لا تكفي نسخة ملف رئيسي أثناء كتابة متزامنة. تُحفظ النسخة في وجهة خاصة يختارها المستخدم مع تحذير plaintext. تُختبر الاستعادة في هدف منفصل قبل الاعتماد. لا تتلف النسخة أو الأصل.
3. **فحص قبل الكتابة:** التحقق من إصدار المصدر وصيغته والحدود والمعرفات والتعارضات وملكية الوجهة. رفض مسارات غير موثوقة أو غير آمنة وفق سياسة المضيف. مصدر غير مدعوم أو تالف يُوقف الترحيل دون تعديل.
4. **هدف منفصل:** يُنشأ مخزن v2 جديد، وتُنسخ البيانات في معاملة أو آلية استعادة قابلة للتعافي. تُحفظ المعرفات متى كانت آمنة وغير متعارضة، وإلا يُسجل ربط مصدر/هدف صريح يمكن التحقق منه؛ لا دمج أو استبدال صامت.
5. **تحقق واستعادة:** مقارنة العدد والمحتوى والروابط، وإغلاق العملية وإعادة فتحها، واختبار رفض وصول وكيل غير مخول. يراجع المستخدم النتيجة؛ أي فشل يترك الأصل والنسخة القابلة للاستعادة كما كانا.
6. **التفعيل:** التبديل إلى الهدف إن أمكن بصورة ذرية ومع موافقة منفصلة؛ لا حذف أو إعادة تسمية أو استبدال للأصل أو النسخة القديمة دون إذن مستقل وخطة رجوع. لا وعود بمحو آمن لنسخ أو WAL أو وسائط التخزين.

إسناد الملكية وترحيل النسخ لا يعنيان تشفير البيانات. عند إضافة خزنة في مرحلة لاحقة ستحتاج عملية ترحيل أخرى واضحة، مع حفظ الأصل والتحقق من الاستعادة وتقييم المفاتيح. لا تختبر الخطة تلقائيًا ما يزيد على حدود v1 أو معالجة بيانات إنتاجية.

## اختبارات مطلوبة قبل أي ترحيل

فشل كل مرحلة، وملف تالف وإصدار غير مدعوم ومصدر أثناء الكتابة مع WAL، وتعارض المعرفات، وإسناد مالك خاطئ أو مرفوض، وفشل النسخة/الاستعادة، وتعطل أثناء النقل أو التفعيل، وتكرار المحاولة؛ يُثبت أن الأصل قابل للقراءة وأن الهدف غير جزئي أو غير مفعل عند الفشل. الاختبارات التفصيلية في [المصفوفة](k2-acceptance-matrix.md)؛ لم تُنفذ بعد.
