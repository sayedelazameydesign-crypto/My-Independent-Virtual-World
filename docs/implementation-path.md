# تصور التنفيذ الأولي السابق

> **حلّ محله [مسار المشروع القائم](existing-project-plan.md).** كان هذا مقترحًا قبل الإبلاغ عن مشروع Lovable؛ لا تبدأ مشروع Python/SQLite جديدًا بناءً عليه، ولا تفترض أنه يصف الشيفرة الحالية.

## الهدف الأول

بناء نسخة أولى محلية لمستخدم واحد، بلا حساب أو استضافة أو خدمة مدفوعة: مساحة مرئية ثنائية الأبعاد بسيطة ولوحة عربية/إنجليزية، متصلتان بنواة فعلية تحفظ عناصر مساحة العمل والمهام والملاحظات في SQLite. يمكن إنشاء العناصر وتعديلها وحذفها وعرضها بعد إعادة التشغيل، وتصدير البيانات واستعادتها. الذكاء الاصطناعي اختياري ويُعرض بأنه غير متاح إلى أن يُنفذ ويُختبر محوله؛ لا ردود وهمية ولا أزرار توحي بعمل تكامل غير موجود.

هذه وثيقة تكليف، وليست تقرير تنفيذ. المستودع المستهدف هو `sayedelazameydesign-crypto/My-Independent-Virtual-World`؛ العمل يكون على فرع جلسة العمل الحالي. لا حاجة لإنشاء مستودع أو مشروع Lovable أو خدمة خارجية. لم تُتحقق حالة أي مساحة Lovable أو خطتها في هذه الجلسة.

## اختيارات الإصدار الأول

| المجال | القرار | السبب والحد |
|---|---|---|
| النواة | Python 3.11 أو أحدث، باستخدام المكتبة القياسية قدر الإمكان | سهولة تشغيل محلي دون اعتماد على خدمة؛ تثبيت Python مسؤولية المستخدم |
| البيانات | SQLite عبر `sqlite3` ومعاملات واضحة وإصدارات للمخطط | ملف محلي قابل للنسخ؛ ليس قاعدة مشتركة متعددة المستخدمين |
| الواجهة | HTML وCSS وJavaScript دون إطار عمل في البداية، مع عرض ثنائي الأبعاد قابل للاستخدام من لوحة المفاتيح | تقليل التبعيات؛ ليست تجربة ثلاثية الأبعاد كاملة |
| الاتصال | واجهة HTTP محلية، بمسارات نسبية من المتصفح، والواجهة وسطر الأوامر يستدعيان نفس خدمات النواة | الواجهة ليست مخزن الحقيقة؛ لا تستدعي JavaScript عنوان localhost ثابتًا |
| التصدير | ملف JSON بإصدار مخطط للبيانات المنظمة فقط في النسخة الأولى | لا يتضمن أسرارًا أو مرفقات؛ التشفير والمرفقات مؤجلان مع تحذير واضح |
| الاختبارات | `unittest` واختبارات عملية للنواة وHTTP وSQLite | تشغيل دون خدمة خارجية؛ تُوثق الاختبارات اليدوية للواجهة أيضًا |
| الذكاء | عقد مستقل، ثم محول محلي اختياري لاحقًا بعد التحقق | دون تنزيل نموذج أو ادعاء عمله في النسخة الأولى |

خادم المكتبة القياسية مناسب للتطوير المحلي فقط، وليس للنشر العام أو الإنتاج. افتراضيًا يستمع إلى واجهة loopback؛ إن استُخدمت معاينة خارجية تتطلب `0.0.0.0` فتحتاج ضوابط وصول صريحة ومراجعة أمنية، ولا تُعرض بيانات شخصية حقيقية. يُرفض الطلب غير الموثوق من المتصفح ويتحقق الخادم من `Host` و`Origin` ويستخدم حماية CSRF للعمليات المعدِّلة؛ لا يُفترض أن واجهة loopback وحدها آمنة. لا وصول عام أو مصادقة متعددة المستخدمين في الإصدار الأول.

## حزم العمل بالتسلسل

### 1. الأساس والذاكرة الحقيقية

- إنشاء بنية صغيرة للنواة والاختبارات، وإعداد مسار بيانات محلي قابل للضبط لا يُضاف إلى Git، وتهيئة قاعدة البيانات ومخططها بإصدار محدد.
- تنفيذ إنشاء وقراءة وتعديل وحذف عناصر تتضمن معرفًا ثابتًا ونوعًا وعنوانًا ومحتوى وتواريخ، مع التحقق من المدخلات ومعاملات SQLite.
- توفير سطر أوامر محلي يستخدم النواة نفسها، وتعليمات تثبيت وتشغيل من نسخة نظيفة.
- **بوابة قبول:** اختبار CRUD ثم إغلاق العملية وفتح قاعدة البيانات مجددًا، واختبار إدخال غير صالح وفشل قاعدة البيانات دون الإبلاغ عن نجاح كاذب.

### 2. التصدير والاستعادة

- تصدير JSON بإصدار تنسيق وبيانات منظمة فقط، دون أسرار؛ إظهار تحذير بأنه غير مشفر.
- فحص البنية والإصدار والقيود قبل الاستعادة. في النسخة الأولى تكون الاستعادة إلى قاعدة فارغة فقط؛ عند وجود بيانات تُرفض العملية برسالة واضحة، فلا استبدال أو دمج صامت.
- تنفيذ الاستعادة في معاملة واحدة مع التراجع عند الخطأ؛ اختبار التلف والنسخ غير المدعومة.
- **بوابة قبول:** إنشاء بيانات، وتصديرها، واستعادتها إلى قاعدة فارغة، ومقارنة المحتوى والمعرفات، والتأكد من عدم تغير قاعدة موجودة أو ترك بيانات جزئية عند الفشل.

### 3. الواجهة والعالم المرئي

- توفير HTTP API محلية لخدمات النواة، ولوحة تعرض عناصر حقيقية وتسمح بتعديلها، مع خريطة/مساحة ثنائية الأبعاد مرتبطة بالعناصر لا مجرد صورة ثابتة. تحفظ مواضع العناصر محليًا كبيانات فعلية.
- دعم العربية والإنجليزية واتجاه النص، والتنقل بلوحة المفاتيح، وحالات التحميل والخطأ والفراغ. وظائف التصدير والاستعادة واضحة؛ كل إجراء مؤثر يشرح نتيجته.
- تنفيذ ضوابط HTTP المحلية أعلاه قبل استخدام الواجهة؛ عدم تمكين CORS المفتوح أو تنفيذ أوامر نظام عبر API.
- **بوابة قبول:** تشغيل فعلي من نسخة نظيفة؛ إنشاء عنصر ونقله وتحديث الصفحة وإعادة تشغيل الخادم والتحقق من بقائه، ثم تجربة فشل API والاستعادة والضوابط الأمنية. تسجيل ما اختُبر يدويًا وما لم يُختبر.

### 4. الذكاء والاستمرارية

- تعريف واجهة مزود محايدة وسياسة تعطيل افتراضية؛ اختيار محول محلي واحد فقط بعد مراجعة متطلبات الجهاز والترخيص. لا تنزيل تلقائي للنماذج. استخدام عنوان محلي موثوق مُعد صراحة، وعدم قبول عناوين عشوائية من الواجهة.
- إظهار عدم توفر النموذج أو فشل الاتصال؛ لا تحويل إلى أي خدمة خارجية دون تفعيل وموافقة يحددان الوجهة والبيانات والتكلفة المحتملة.
- **بوابة قبول:** اختبار عقد المحول بمزود اختبار واضح التسمية، ثم اختبار فعلي للنموذج إن توفر، واختبار توقفه. إن لم يوجد بديل مؤهل تُعرض حالة عدم التوفر؛ لا يوصف مزود الاختبار بأنه ذكاء حقيقي.

### 5. التكاملات الاختيارية

- مراجعة واجهات وتراخيص CeliaOS وphone-google قبل أي تكامل؛ يبقى dr.mukhtar مستقلًا. يُدرس GitHub وDrive عبر محولات منفصلة وأقل صلاحيات، دون الاعتماد عليهما لتشغيل النواة.
- لا ربط حساب أو إرسال بيانات أو كتابة خارجية أو إنشاء خدمة أو نشر دون موافقة صريحة على العملية والوجهة والصلاحيات؛ تخزين الأسرار خارج Git والتصدير.
- **بوابة قبول:** نجاح فعلي بإذن المستخدم، ورفض أو انتهاء صلاحية، وتوثيق الاختبارات غير المنفذة. لا خدمة مدفوعة دون موافقة مسبقة؛ المجانية أو عدم الفوترة لا يمكن ضمانهما من التطبيق وحده.

## تعريف الانتهاء لكل حزمة

تتضمن تعليمات تشغيل واضحة، واختبارات قابلة لإعادة الإنتاج ونتائجها، وحدودًا معلنة؛ تُختبر البيانات بعد إعادة التشغيل، والفشل والبديل المؤهل أو غيابه حيث ينطبق. لا يُعد وجود واجهة أو كود دليلًا على نجاح تكامل. تُسجل تكلفة ومتطلبات الجهاز وأي اختبار تعذر تنفيذه دون ادعاء نجاحه.

## التكليف التالي للوكيل

ابدأ **بالحزمة 1 فقط** داخل هذا المستودع، دون تغيير مشروعات أخرى أو إنشاء خدمات خارجية. أنشئ النواة والتخزين وسطر الأوامر والاختبارات والتعليمات، ثم شغّل الاختبارات من نسخة محلية وأبلغ بالنتائج والنواقص. لا تبنِ واجهة شكلية ولا تدّعِ وجود ذكاء اصطناعي أو تكامل خارجي. بعد استيفاء بوابة القبول انتقل إلى الحزمة 2 بموافقة المستخدم أو ضمن تكليف لاحق.
