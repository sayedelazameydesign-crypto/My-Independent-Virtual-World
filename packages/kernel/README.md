# نموذج نواة MIVW مستقل

وحدة TypeScript تجريبية مستقلة عن مشروع Lovable الذي لم يصل مصدره بعد. تنفّذ خطة صريحة ومحدودة لملاحظات محلية، لا نموذج ذكاء اصطناعي ولا وكيلًا مستقلًا يتخذ قرارات أو يستخدم أدوات عامة. دورة التشغيل تبيّن الفهم والتخطيط والتنفيذ والملاحظة والمراجعة لخطوات محددة مسبقًا، وتتوقف عند أول رفض أو فشل؛ لا تتراجع عن خطوات سابقة نجحت.

## التشغيل والاختبار

تتطلب Node.js 22.13 أو أحدث وnpm. محول SQLite يستخدم `node:sqlite` التجريبي في Node 22؛ قد يظهر تحذير وتختلف واجهته مستقبلًا. يتطلب التثبيت اتصالًا بسجل npm لتثبيت تبعيات التطوير المثبتة إصداراتها في ملف القفل. لا تتطلب حسابًا أو خدمة أو مفتاحًا. من هذا المجلد:

```sh
npm ci --ignore-scripts
npm run lint
npm run typecheck
npm test
npm run build
```

`npm test` يبني الوحدة ثم يشغّل اختبارات Node. يفحص `npm run lint` مصدر TypeScript واختبارات JavaScript باستخدام Biome. لم تُشغّل فحوص مشروع Lovable ولم يُختبر الدمج معه. راجع [إعداد CI](../../docs/ci.md) للفحوص وحدودها.

## مثال محلي

بعد البناء، يمكن للتطبيق المضيف الموثوق استخدام الوحدة هكذا:

```js
import { Kernel } from './dist/index.js';

const kernel = new Kernel({
  permissions: { assistant: ['notes.create', 'notes.read'] },
  // مثال للاختبار فقط: في تطبيق حقيقي اطلب موافقة المستخدم على المحتوى.
  approveCreate: async ({ agentId, action }) => agentId === 'assistant' && action.text === 'تجربة',
});
const result = await kernel.run('assistant', [
  { kind: 'notes.create', text: 'تجربة' },
  { kind: 'notes.read', id: '1' },
]);
console.log(result.status, result.observations);
```

## العقد والحدود الأمنية

- المضيف الموثوق يحدد هويات الوكلاء والصلاحيات عند إنشاء النواة؛ تُنسخ قائمة الصلاحيات ولا يمكن تغييرها عبر طلب الخطة. يجب على المضيف التحقق من الهوية بنفسه: معرف `agentId` وحده **ليس مصادقة** ويمكن انتحاله إذا استُخدمت الواجهة مباشرة من مصدر غير موثوق.
- الصلاحيات الوحيدة `notes.read` و`notes.create`، على مستوى النواة كلها لا على مستوى الملاحظة أو المالك. قراءة أي ملاحظة تتطلب صلاحية القراءة ومعرفة معرفها، لكنها ليست حماية لعزل المستخدمين. لا أوامر نظام أو شبكة أو مزود ذكاء.
- إنشاء كل ملاحظة يحتاج صلاحية إنشاء وقرار `true` صريحًا من دالة موافقة يزوّدها المضيف؛ لا موافقة تعني رفضًا. الموافقة مرتبطة بنسخة ثابتة من العملية ومحتواها. مثال الموافقة التلقائية أعلاه للتوضيح فقط وليس موافقة مستخدم حقيقية.
- الخطة محددة بحد أقصى 20 خطوة، وتُفحص كاملة قبل البدء. يبدأ التنفيذ عند النجاح في التحقق، ويتوقف على أول خطأ أو رفض؛ يُعيد الحالات دون تفاصيل أخطاء قد تحتوي أسرارًا. لا يوجد إلغاء لطلب موافقة معلّق، أو انتهاء مهلة تلقائي.
- سجل الأحداث محلي مؤقت ويحتوي معرف الوكيل ونوع الإجراء والحالة فقط، لا محتوى الملاحظات. لا تُسجل الخطط غير الصالحة أو الوكلاء المجهولون؛ لا يُعد هذا سجل تدقيق أمني شاملًا.
- المخزن الافتراضي والسجل **في الذاكرة فقط** ويضيعان عند انتهاء العملية. يمكن للمضيف الموثوق اختيار محول SQLite المحلي أدناه؛ لا يوجد تخزين دائم للسجل. لا توجد حدود إجمالية لعدد الملاحظات أو الاحتفاظ بالسجل.
- الوحدة مكتبة تعمل ضمن صلاحيات التطبيق المضيف، وليست sandbox أو بيئة عزل أو إدارة أسرار. الكود غير الموثوق الذي يعمل في العملية نفسها يستطيع تجاوزها. لا تُستخدم لإسناد صلاحيات حساسة قبل وجود طبقة منفصلة موثوقة، ومصادقة، ومراجعة أمنية.


## تخزين SQLite والنسخ الاحتياطي (Node فقط)

هذا المحول منفصل عن واجهة المتصفح، ولا يستخدم IndexedDB ولا يتصل بمشروع Lovable. يختار المضيف ملفًا داخل مجلد خاص بالمستخدم خارج Git؛ يُنشأ الملف الجديد بصلاحيات مقيدة قدر الإمكان (وضع `0600` على الأنظمة التي تدعمه)، لكن صلاحيات الملفات الموجودة والمجلد والنسخ الاحتياطية مسؤولية المضيف. قاعدة SQLite والنسخة غير مشفرتين. تدعم نسخة الاحتياط حتى 10,000 ملاحظة و50 MiB؛ تُرفض الصيغ المجهولة أو التالفة أو المكررة. الاستعادة إلى قاعدة فارغة فقط وفي معاملة واحدة. عمليات النسخ والاستعادة متاحة **للمضيف الموثوق فقط** وليست أدوات وكيل؛ عليه طلب موافقة المستخدم وحماية الملف الوجهة. لا تصدّر أو تحفظ أي أسرار ضمن الملاحظات.

```js
import { Kernel } from './dist/index.js';
import { SqliteNoteStore } from './dist/node.js';

const store = new SqliteNoteStore('/مسار/خاص/mivw.sqlite');
const kernel = new Kernel({
  store,
  permissions: { assistant: ['notes.create', 'notes.read'] },
  // مثال توضيحي فقط؛ يجب استبداله بموافقة مستخدم حقيقية قبل التنفيذ.
  approveCreate: async () => true,
});
await kernel.run('assistant', [{ kind: 'notes.create', text: 'ملاحظتي' }]);
// بعد موافقة المستخدم: const plaintextBackup = store.exportBackup();
// الاستعادة لقاعدة فارغة فقط: emptyStore.restoreBackup(plaintextBackup);
store.close();
```

فشل المخزن يُرجع `failed` ولا يتحول بصمت إلى ذاكرة مؤقتة. تستمر أذونات الوكيل بالتحكم في التنفيذ عبر `Kernel`، لكن من يملك كائن المخزن يستطيع الوصول مباشرة؛ لذلك لا تسلّم هذا الكائن أو واجهات النسخ إلى كود غير موثوق. مسارات الملفات يتحكم فيها المضيف، وليست مدخلات وكيل. لا توجد واجهة مستخدم أو تشفير أو مزامنة أو نسخ تلقائي.
